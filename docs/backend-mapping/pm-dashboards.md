# Project Management dashboards: frontend ↔ backend mapping

Feature: `src/features/project-management/components/dashboards/` (sidebar → Project Management → Home,
Workspace, Project and Task Dashboard). Data: `hooks/use-dashboards.ts`, `api/dashboards.api.ts`, and the
module's own `api/pm.api.ts` / `hooks/use-pm.ts` (unchanged). Mock of the pending endpoints:
`src/mocks/project-management/dashboard-handlers.ts`. Routes: `src/routes/_app/project-management/{home,
workspace-dashboard,project-dashboard,task-dashboard}.tsx`. Tests: `src/features/project-management/
dashboards.test.tsx`. Requirement: BRD row 19 "Dashboards" (`HRango - Project Management BRD/README.md`). No
Figma frame exists for any dashboard; the look follows the module (purple `#7127EA`, `#ECECEC` cards, Poppins).

## How the dashboards read data

- There is no cross-workspace or dashboard endpoint (Backend Dependencies T7). Every figure is computed in the
  browser from calls the module already makes, with the same query keys, so the cache is shared with the
  workspace page:
  - `GET /projects/workspaces` (all pages): the workspaces in scope, hidden ones left out as in the panel.
    Home counts only workspaces the caller is a member of (`myRole` set); the other three every readable one.
  - for each workspace in scope, `GET /projects/workspaces/{id}` (+ `column-permissions`, `custom-fields`, as
    `pmApi.workspace`) for statuses, folders, lists and members, and `GET /projects/workspaces/{id}/tasks`
    (all pages, `groupBy=none&subtasks=expanded`) for every task with status, assignees, dates, `isOverdue`,
    `isClosedLate`, story points, estimate, time tracked, comment and attachment counts.
  - The hero of each dashboard says what it covers ("Covers 3 workspaces you can open"), and names any workspace
    that could not be read (left out of the figures).
- A task is **done** when its status is in the Done or Closed group; **in progress** when in the Active group.
  Weeks start on Sunday (as the module's Calendar view and date quick picks).
- Every Project Management mutation invalidates `['project-management']`; the dashboards' own keys sit under it,
  so they refresh after any change. While refreshing, the previous figures stay on screen, slightly faded.
- The workspace history endpoint (`GET …/activity`) is **not** used (it is the Activity view's, per workspace and
  paged). "Latest Activity" is derived from each task's `createdAt`, `closedAt` and `latestComment`, and says so.

## States

- **Loading**: card-shaped skeletons (hero figures and four widgets); each widget has its own skeleton.
- **Empty**: no workspace → "No workspaces yet" with Create Workspace (`projects.workspaces.create`); every widget
  has its own empty message.
- **Error**: the workspace list fails → "Could not load this dashboard" with Try again; one widget's call fails
  → that widget's error with Try again; a workspace that fails is left out and named in the hero.
- **No access**: without `projects.workspaces.view` → "No access to Project Management"; a workspace answering
  403 / 404 → "You cannot open this workspace"; a missing folder → "This project is not here".
- **Pending endpoints**: against the real API a 404 / 405 / 501 shows "Not available yet (Backend Dependencies
  T…)". In mock mode the mock answers and the widget carries a "Sample data" badge (with the reason for screen
  readers), so mocked data is never presented as finished.

```
DocSummaryOut { id, workspaceId, title, folderId: id | null, listId: id | null, ownerName: string | null,
                wordCount: number, updatedAt }            // DocOut (T1) without the content

POST  /api/projects/personal-list { title, dueDate } → { data: PersonalItemOut }
PATCH /api/projects/personal-list/{id} { done, rowVersion } → { data: PersonalItemOut }   // 409 on a stale rowVersion
DELETE /api/projects/personal-list/{id}?rowVersion= → 204
```

Each pending call is marked `// TODO(backend): endpoint not available` in `api/dashboards.api.ts` and answered
only by `src/mocks/project-management/dashboard-handlers.ts` (registered in `src/mocks/handlers.ts`).

## Scale

A dashboard over N workspaces makes 2N reads (each workspace and its task list, every page), plus one comments
read per task with comments (Home) and one attachments read per task with files (Workspace, Project). That is
fine for a few workspaces of a few hundred tasks; the T7 aggregates above are the answer beyond that.
